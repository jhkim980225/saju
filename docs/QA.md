### E2E 환경 원칙
- **분리된 서버:** API `:4100`, Web `:5180` 로 새로 띄운다. 개발 서버(4000/5173)와 겹치지 않는다. Web 은 `VITE_API_BASE_URL=http://localhost:4100/api/v1`, API 는 `CORS_ORIGINS` 에 `http://localhost:5180` 을 넣는다.
- **임시 DB:** `apps/api/data/e2e.db` 를 매 실행 시작 때 지우고 새로 만든다(`e2e/support/start-api.mjs`, 파일 이름에 `e2e` 가 없으면 지우지 않는 안전장치 포함).
- **외부 네트워크 차단:** localhost 이외 요청(폰트 CDN·분석·광고·결제 SDK)은 픽스처에서 모두 차단한다. 결제는 mock, AI 키는 비워서 규칙 기반 답변을 쓴다.
- **모바일 기준:** 390×844, `isMobile`, 터치, `ko-KR`, `Asia/Seoul`, 라이트 색상 모드.
- **데스크톱:** 같은 시나리오를 1440×900(`desktop-chromium` 프로젝트)에서도 실행한다 — 상단 내비, 2단 화면, 가운데 대화상자. 전체 76개.
- **데이터 독립성:** 테스트마다 새 게스트·회원을 만든다. 병렬(워커 3)로 돌려도 서로 영향을 주지 않는다. 화면과 무관한 준비(가입·프로필·구매)는 API 로 하고, 세션은 `localStorage['yd.session']` 에 주입한다(`e2e/support/fixtures.ts`).
- **요청 제한:** 같은 IP 에서 계정을 많이 만들기 때문에 E2E 서버에서는 `RATE_LIMIT_PER_MIN`·`AUTH_RATE_LIMIT_PER_MIN` 을 크게 잡는다. 운영 값 검증은 API 통합 테스트(`security.test.ts`)가 맡는다.
- **선택자:** 역할·접근 가능한 이름·화면 문구(`apps/web/src/i18n/ko.json`)를 쓴다. 클래스 선택자는 꼭 필요한 곳(궁합 점수 숫자)에만 쓴다.

## 2. 실행 방법

```bash
npm install                        # 루트 — @playwright/test 1.64 포함
npx playwright install chromium    # 최초 1회 (이미 있으면 생략)
npm run test:e2e                   # API(:4100)·Web(:5180) 자동 기동 → 전체 실행 → 서버 종료
```

| 하고 싶은 일 | 명령 |
|---|---|
| 파일 하나만 | `npx playwright test e2e/purchase.spec.ts` |
| 제목으로 고르기 | `npx playwright test -g "궁합"` |
| 브라우저를 보며 | `npx playwright test --headed --workers=1` |
| 디버그(한 단계씩) | `npx playwright test e2e/today.spec.ts --debug` |
| UI 모드 | `npx playwright test --ui` |
| 반복 실행(불안정 테스트 찾기) | `npx playwright test --repeat-each=3` |
| 리포트 열기 | `npx playwright show-report` (`playwright-report/`, git 제외) |
| fixme 재현 확인 | 해당 `test.fixme(` 를 잠시 `test.only(` 로 바꿔 실행 |

- 설정: `playwright.config.ts` (retries 0, `trace: on-first-retry`, 실패 시 스크린샷, 리포터 list + html)
- 포트 바꾸기: `E2E_API_PORT`, `E2E_WEB_PORT` 환경 변수
- 4100/5180 을 다른 프로세스가 쓰고 있으면 기동이 실패한다(`reuseExistingServer: false` — 임시 DB 를 매번 새로 쓰기 위해서다).
- 결과물: `test-results/`(실패 스크린샷·에러 컨텍스트), `playwright-report/`, `apps/api/data/e2e.db` — 모두 git 에서 제외된다.

### BUG-02 — 사주 수정 후 이전 풀이가 그대로 보임 (중간)
- **재현:** 저장한 사주 `/saju/:id` 를 연다(갑진일주) → “입력 정보 수정” → 생년월일을 1995.03.15 로 바꿔 저장 → `/saju/:id` 로 돌아옴
- **기대:** 을사일주, “양력 1995.03.15”
- **실제:** 갑진일주, “양력 1995.03.14” 가 그대로 보인다. 새로고침하거나 30초(staleTime) 뒤 다시 들어와야 바뀐다. 오늘의 운세(주간 흐름은 10분)·신년운세·궁합 캐시도 같은 문제가 있다. 출생 시간을 바로잡으려고 수정한 사용자는 수정이 안 된 것으로 보거나 틀린 결과를 믿게 된다.
- **원인:** `apps/web/src/pages/BirthFormPage.tsx` 저장 시 `qk.profiles` 만 무효화한다. `['reading','profile',id,…]`(`MySajuPage.tsx`), `['daily',id,…]`(`TodayPage.tsx`), `['yearly',id,…]`, `['compat',…]` 는 그대로 남는다.
- **제안:** 수정 성공 시 해당 프로필 ID 가 들어간 쿼리를 모두 무효화하거나 `removeQueries` 로 지운다.

### BUG-05 — 2027년 1월부터 신년운세 진입로가 2028년으로 넘어감 (중간, 날짜가 되면 발생)
- **재현:** 브라우저 시각을 2027-01-15 로 둔다(테스트는 `page.clock`) → 내 사주 화면
- **기대:** “2027 신년운세” 바로가기 → 2027 정미년 화면, 단품(정가 7,900원)·패키지 결제 가능
- **실제:** “2028 신년운세” → 2028 무신년 화면. 버튼은 가격 없이 “전체 보기”, 결제 시트는 “지금 구매할 수 있는 상품이 없어요”. 판매 중인 2027 신년운세로 가는 화면 진입로가 사라진다.
- **원인:** 웹이 연도를 항상 `new Date().getFullYear() + 1` 로 정한다 — `apps/web/src/pages/YearlyPage.tsx`(기본 연도), `MySajuPage.tsx`·`TodayPage.tsx`(바로가기 문구·링크). 서버 `apps/api/src/modules/interpretation/reading.ts` 는 “10월부터 다음 해” 규칙을 써서 서로 다르다.
- **제안:** 신년운세 대상 연도를 한 곳(예: shared 의 `targetYearlyYear(now)`: 10~12월은 다음 해, 1~9월은 올해)에서 정하고 웹·API 가 같이 쓴다. 판매 상품 존재 여부와도 맞춘다.

### BUG-01 — 결과 “섹션 바로가기”에 빈 칩 4개 (낮음~중간)
- **재현:** 어떤 사주든 결과(`/result`) 또는 내 사주 화면 → 상단 고정 섹션 바로가기 줄
- **기대:** 칩마다 섹션 이름(예: 오행 분석, 나에게 필요한 기운, 나의 신살, 십신으로 본 나의 성향)
- **실제:** `#sec-elements`, `#sec-yongsin`, `#sec-shinsal`, `#sec-tenGods` 칩이 글자 없는 빈 알약으로 보인다. 스크린리더에서도 이름 없는 링크다.
- **원인:** `apps/web/src/components/ReadingSection.tsx` 의 `sectionLabels()` 가 `SECTION_COPY` 에 없는 키에는 `label: ''` 를 돌려주고, `ReadingView.tsx` 의 바로가기 칩이 그 `label` 만 쓴다.
- **제안:** 라벨이 없으면 `section.title` 로 대체하거나, 해당 키를 카피에 추가한다.
- E2E 접근성 스모크는 이 칩만 알려진 이슈로 제외하고 있다(`a11y.spec.ts` 의 `KNOWN_UNNAMED`). 고친 뒤에는 제외 목록을 비운다.

### BUG-04 — 미주 시간대에서 오늘 화면 요일이 하루 밀림 (낮음)
- **재현:** 브라우저 시간대를 `America/Los_Angeles` 로 두고 `/today` (KST 2026-10-12 월요일)
- **기대:** “10월 12일 월요일”
- **실제:** “10월 12일 일요일”
- **원인:** `apps/web/src/pages/TodayPage.tsx` 의 `new Date(date).getDay()` — `YYYY-MM-DD` 를 UTC 자정으로 해석한 뒤 현지 시각으로 요일을 구한다. 서울처럼 UTC+ 시간대에서는 드러나지 않는다. 해외 출생지를 지원하므로 해외 사용자도 있다.
- **제안:** 이미 있는 `weekdayOf(iso)`(`lib/format.ts`)를 쓴다.

### BUG-03 — 다음 해 운세에 “올해의 운세” 라벨 (낮음)
- **재현:** 2026년 10월에 결과 화면을 연다
- **실제:** 섹션 키 `year2027`(“2027년, 나의 계절”)의 라벨이 “올해의 운세”다. 잠금 카드에도 “올해의 운세의 나머지 내용…”으로 나온다. 랜딩의 미리보기는 “2026년, 나의 계절”이라 결과와도 다르다.
- **관련:** `apps/web/src/components/ReadingSection.tsx` `sectionLabels()`(year 키 → `result.sections.thisYear`), `apps/web/src/pages/LandingPage.tsx`(미리보기 연도), `reading.ts` 의 연도 규칙
- **제안:** 대상 연도가 올해가 아니면 “2027년 운세”처럼 연도를 붙인 라벨을 쓴다. BUG-05 와 같은 연도 규칙으로 맞춘다.

### 참고 (버그 아님 · 의도된 변경 반영)
- 보안 리뷰에 따른 동작 변경을 E2E 기대값에 반영했다. 규칙 기반 상담은 잠긴 주제를 물으면 잠금 안내와 함께 성격 풀이로 답한다. 구매한 사주는 출생 정보를 바꾸면 409가 난다. 기존 회원으로 로그인하면 게스트 사주를 병합한다. 계정당 1회 상품의 두 번째 결제는 거절된다.
- `index.html` 이 웹 폰트(Pretendard·Noto Serif KR)를 외부 CDN 에서 불러온다. E2E 는 이를 차단하고 돌리며 기능에는 영향이 없다. 앱(Capacitor) 오프라인 첫 실행이나 CDN 장애 때는 기본 글꼴로 보이므로, 앱 빌드에서는 폰트 번들링을 검토할 것.
