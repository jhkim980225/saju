## 0. 요약 (TL;DR)

1. **사주아이(saju-kid.com)에는 아직 타로가 없습니다.** 번들 코드에 타로 캐릭터 '모찌요정'(핑크 요정 옷을 입은 햄스터 실사 사진, `comingSoon`)이 준비되어 있어, 카드 펼침형 상품이 아니라 **연애 특화 채팅 캐릭터**로 낼 것으로 보입니다 [확인/추정]. 사주아이에서 가져올 것은 타로 UI가 아니라 **운영 원칙**입니다: 990원 단건, "일부를 무료로 읽어 본 뒤 결제", 기간 제한 없는 보관함, 공유 범위 선택, `prefers-reduced-motion` 대응.
2. 국내 타로는 네 갈래입니다.
   - **채팅 캐릭터형**: 헬로우봇 라마마, 도사, 사주GPT, 토샤
   - **상품 페이지형**: 포스텔러 프리미엄 '운명책', 마이타로
   - **광고·재화 게이트형**: 점신 "광고 시청하고 결과보기", 오즈의타로 별사탕
   - **사주 결합형**: 운빨 '사주 결합 타로', 마이타로 사주타로
   
   무채색·타이포 중심의 '조용한 타로'는 국내에서 찾지 못했습니다(빈자리).
3. 흐름의 공통 문법은 `주제 → (질문) → 섞기 → N장 고르기 → 뒤집기 → 결과`입니다.
   - 고르기 방식: 22장 그리드(포스텔러·신비운), 부채꼴(포스텔러 무료·헬로우봇), 78장 캐러셀(도사), 자동 뽑기(Labyrinthos 옵션·Golden Thread)
   - **자리를 먼저 말해 주고 고르게 하는 방식**("세 번째 카드는 그 사람이 너를 생각하는 마음을 떠올리며 골라 줘" — 헬로우봇)이 한 장 한 장에 의미를 줍니다.
4. **권장 흐름(여덟자)**
   - 질문 타로: 주제 1탭 → 질문(선택) → 자동 섞기 1.2초 → 78장 가로 띠에서 N장 고르기(자리 안내 + '알아서 골라 주세요') → 한 장씩 탭해 펼치기 → 결과. 4장 기준 최소 7~10탭.
   - 오늘의 카드: 2탭, 하루 1장 고정.
5. **카드 그림: MVP는 자체 '먹선 카드'(타이포 + 기호 SVG 78장).**
   - 1909년 패멀라 콜먼 스미스 원화는 한국에서 **2002-01-01부터 퍼블릭 도메인**입니다. 회복저작물 부칙 + 당시 사후 50년 + 2011년 개정의 비소급 [확인]. 미국(1931년 이전 발행)·영국·EU도 퍼블릭 도메인입니다.
   - 위험은 원화가 아니라 다른 데 있습니다: **U.S. Games 재채색판(1971·Radiant·Universal Waite), 제3자 '복원' 스캔, 'Rider-Waite' 계열 상표 10건**.
   - 1909년 스캔은 2차 '고전 그림 보기' 옵션으로만 두고, 출처는 Wikimedia Commons 'Roses & Lilies' 1909 초판 세트로 합니다.
6. **결과 구조**: 질문 → 펼친 카드 → 카드가 건네는 한 줄 → 카드 블록(자리·이름·정/역·키워드·전통 의미·전통 그림 묘사·질문 맞춤 풀이·읽은 이유) → 총평 → 이렇게 해 보세요 → 메모 → 공유·기록 → 면책.
7. **잠금 경계**
   - 무료: **카드와 전통 의미는 항상 무료**입니다.
   - 유료 '깊은 풀이': 자리별 질문 맞춤 풀이·카드 간 연결·총평 전체·행동 3개.
   - 잠금 방식: 기존 정직한 잠금(실제 첫 문단 + 페이드 + 유료 목차)을 그대로 씁니다.
   - 결제해도 **카드는 바뀌지 않습니다**. 다시 뽑기·광고 시청 게이트·점수는 쓰지 않습니다.
8. **전문가 표현**: 가짜 '○년 경력 타로 마스터'·가상 상담사·검증 불가 숫자는 쓰지 않습니다(표시광고법, 공정위 추천·보증 심사지침 2026-06-01 시행). '사람' 대신 **해석 기준**('여덟자 타로는 이렇게 읽어요')과 **카드별 근거**를 보여 줍니다. 가이드 캐릭터는 MVP에서 권장하지 않습니다.

## 3. 서비스별 관찰

### 3.1 사주아이 (saju-kid.com) — 기준 서비스

**타로 유무** [확인]
- `/tarot` 경로는 404이고, robots.txt와 사이트맵에도 타로가 없습니다.
- JS 번들의 채팅 캐릭터 목록: 복냥이(`live`), 햄스T(`live`), **모찌요정(타로, `comingSoon`)**, 매화너굴(신점, `comingSoon`).
- 모찌요정 프로필은 핑크 요정 드레스·왕관·지팡이를 한 햄스터 **실사 사진**입니다. 소개는 "‧͙⁺˚*･༓☾사랑.그게.뭔데☽༓･*˚⁺‧͙", 예고 문구는 "타로 카드 챙겨서 가는 중이야! 조금만 기다려 줘 💗", "운명의 카드를 고르고 있어… 조금만 기다려!" → **연애 특화 채팅 타로**로 낼 계획으로 보입니다 [추정].

**비주얼·톤** [확인: CSS·이미지]
- 색: `#F6C94D`(옐로), `#E885AC`·`#F29BB9`(핑크), `#D6336C`, 갈색 텍스트 `#8A7358`.
- 글꼴: IBM Plex Sans KR, Noto Serif KR, Gowun Dodum, Jua, 픽셀 폰트까지 섞여 있습니다.
- 마스코트 **복냥이**는 밈 스타일 고양이 실사 사진(코 클로즈업)이고, "-냥" 말투를 씁니다("오늘의 운세가 나왔다냥!", "난 언제나 네 편이다냥.").
- 카피 예: "요즘 다들 여기서 사주본대", "내 연애에도 스포가 필요해", "냥이가 츄르 먹고 입맛 다시는 중... 👅", "궁금하면 990원에 공유해드림".
- 모션이 많지만(다마고치식 '운세 뽑기' 기계, `motion_cardFlip`, 티켓 컨페티), CSS 3개 파일에서 **`prefers-reduced-motion`을 지킵니다**.

**전문가 '혜산도사'** [확인]
- **사진·일러스트 없이 텍스트로만** 등장합니다: "35년 사주전문가 혜산도사의 수제자", "35년 경력 혜산(慧山)도사님의 통변 노하우를 담아".
- FAQ에서는 수위를 낮춥니다: "해설의 틀은 35년 경력 사주 전문가 혜산도사의 자문을 거쳐 설계했어요. 다만 사주는 앞날을 확정하는 답이 아니라…" → 역할을 '자문'으로 한정한 표기 방식은 참고할 만하지만, 경력은 외부에서 검증할 수 없습니다.
- 숫자: "180만 사주 덕후들의 선택"(메타 태그).

**과금·잠금** [확인]
- 1츄르 = 990원 = 해설 1개. "월 구독료도 자동결제도 없어요".
- "대운과 연도별 운세, 택일은 일부를 무료로 읽어본 뒤에 결제할지 정하면 돼요" → '대운 미리보기 → 대운 전체 해설'.
- 잠금 표현은 blur 유틸리티를 쓰는 것으로 보입니다 [추정].

**입력·결과**
- 입력 확인 화면 "입력하신 내용이 맞나요?" + 만세력 확인을 거쳐 결제합니다.
- 보관함은 "기간 제한 없이" 열람할 수 있습니다.
- 공유 시 "공유 시 공개할 정보를 선택해주세요"로 범위를 고르게 합니다(단, "결제 후 공유가 가능합니다").

**여덟자에의 시사점**
- 가져올 것: 단건 990원대 가격 앵커(가격은 마케팅팀 판단), 미리 읽고 결제, 무기한 보관함, 공유 범위 선택, 모션 감소 대응.
- 가져오지 않을 것: 밈 캐릭터와 '-냥' 말투(먹과 여백·해요체와 충돌), 검증 불가 경력·숫자, 블러 잠금, 결제 후에만 공유 허용.

### 3.2 운빨사주 (saju.s-mon.net) — 사주 결합 타로가 이미 있음

- **진입** [확인]: "78장 풀덱 · 5종 스프레드".
  - 모드를 먼저 고릅니다. **정통 타로** "생년월일 없이 질문과 카드만으로 해석합니다." / **사주 결합 타로** "선택한 사주 명식과 카드를 함께 읽습니다."
  - 이어서 "누구의 타로인가요?" → 스프레드 → 로그인 → 덱 스타일 선택 → 뽑기 순서입니다.
- **스프레드·가격**(자체 재화 '천기', 1원 = 1천기): 원카드 900 · 쓰리카드 1,200 · 연애(5장) 1,500 · 금전(5장) 2,000 · 켈틱크로스(10장) 3,000.
  - 구독 등급마다 열리는 스프레드가 달라집니다(무료 = 원카드 하루 1회 … 맥스 ₩99,000 = 켈틱).
  - AI '사주 대가' 페르소나(강명 선생, 월령 선녀, 지운 도인)와 "100,000명이 선택", "15년 노하우" 문구를 씁니다.
- **카드 그림**: RWS 구도를 단청·민화풍으로 다시 그린 덱 + 검정 바탕 금선 덱. 둘 다 AI 생성으로 보입니다 [추정]. 사이트 색은 금색 `#D4AF37` + 검정 `#0C0C0C`입니다.
- **결과** [확인: 공유 결과 페이지]
  - 질문 → "사주 결합 기준: ○○의 등록 사주와 함께 해석한 기록" → "[1] 오늘의 메시지 / 완드 여왕 / 정방향" → 리딩 요약 → 한 줄 요약 → 카드 해석(방향, 핵심 키워드, 한 줄 메시지).
  - 이어서 **점수**("현재 흐름: 64점 … 리스크: 52점, 행동 권장도: 78점") → 실전 조언 1~3 → 조심할 점 → 마지막 메시지 → "다음에 한 장 더 뽑아보면…" 업셀 → 새로 뽑기 / 공유하기.
- **개인정보 문제** [확인]: `sitemap-tarot.xml`이 공유된 리딩 111건을 검색엔진에 노출하고, 사용자의 질문 원문(임신, 동거 등)과 닉네임이 그대로 들어 있습니다.
  - 여덟자 대응: **공유 결과 페이지는 `noindex`**, 질문은 기본 비공개, URL·OG에 질문을 넣지 않습니다.

### 3.3 포스텔러 — '운명책' 결과가 미학적으로 가장 가까움

- **무료 타로** [확인]
  - 보라 '타로' 라벨, 마스코트 리더가 진행합니다: **아이샤**(집시 소녀 캐릭터, "최애는 BTS 정국!"), **네로**("아이샤의 검은 고양이…반말로 풀이해주는").
  - 웹 뽑기 코드: "질문을 생각하면서 마음이 가는 카드를 선택하세요." → '카드 섞기'(react-spring, 카드가 `rotate(4.2*i-44deg)`로 부채꼴 전개) → 탭 → '카드 선택 취소' 가능 → '선택 완료'.
- **프리미엄 타로** [확인]
  - 금색 '프리미엄' 라벨, 이름을 내건 타로 마스터 저자(루카, 묘묘타로, "라이더 웨이트의 전통을 따르는" 화이트 캣츠 등)의 '저자 소개'가 붙습니다. 가격 4,400~9,900원.
  - 고르기: 22장 그리드, "첫 번째 카드를 선택해주세요. 한번 고른 카드는 다시 되돌릴 수 없습니다. 3장의 카드를 순서대로 신중하게 골라주세요."
  - 결과: 한지 질감 페이지를 넘기는 **'운명책'** — 목차 → CHAPTER 1(폴라로이드 프레임 속 카드) → 명조체 '카드 의미' → 뒤표지 "당신의 미래를 응원합니다."
- 사회적 증거: "…명이 복채를 냈습니다", "900만 유저의 선택", "올해의 브랜드 대상 운세 플랫폼 1위".

### 3.4 점신

- 웹 타로 경로 [확인]: `/tarothome → /selection → /tarotanalyzing → /tarotresult`, 설정의 '타로 스타일 선택'과 카드 의미 사전.
- 상품: 오늘의 타로(1장), 이달의 타로, 궁금한 타로(총운·애정운·재물운·학업&취업운 등), 연애·취업·짝사랑 타로.
- 카피: "카드를 선택해 주세요." / "다시 선택" / "결과 보기" → "선택한 타로를 분석하고 있어요...." → **"광고 시청하고 결과보기"**(보상형 광고로 결과를 막음).
- 카드: 수채·잉크풍 자체 동화 덱 3종(토끼 귀 캐릭터 포함), **메이저 22장만**, 카드 앞면에 이름이 없습니다. 뒷면은 진보라 + 구리색 만다라.
- 본업은 '400명 이상' 전문가 전화 상담(사진 노출)입니다.

## 5. 공통 패턴 / 안티패턴

### 5.1 따라 할 패턴

1. **주제(상황)부터 고르게 하기**: 국내는 재회·속마음·썸 같은 상황형, 해외는 카테고리별 스프레드. → 여덟자는 주제 8개 → 펼침 방식 자동 추천 + 바꾸기.
2. **자리를 먼저 말해 주고 고르게 하기**(헬로우봇·포스텔러 프리미엄 "첫 번째 카드를…"). → `tarot.pick.positionPrompt`.
3. **질문 작성 팁**(Trusted Tarot: 나에게 초점, 예측보다 조언, 구체적으로). → `tarot.question.tips.*`.
4. **모두 뒤집은 뒤에 해석 열기**(Labyrinthos 웹). 뒤집기 연출과 읽기를 분리하면 연출에 몰입하고, 결과 화면은 읽기 좋게 정돈됩니다.
5. **질문형 위치 라벨**(Labyrinthos). → 자리 이름(짧게) + 힌트(질문의 뜻) 2단으로 씁니다.
6. **두 카드 조합 해석**(Trusted Tarot "When these two cards appear together"). → 깊은 풀이의 '카드끼리 이어지는 이야기'.
7. **저널·달력·자주 나온 카드**(Labyrinthos, Mystic Mondays). → 메모 + 월 달력 + `history.frequentCard`. 보상이나 스트릭 없이 돌아보기만 합니다.
8. **역방향 = 180° 회전 + 텍스트 라벨**(Gamespade), **역방향 켜기/끄기**(Labyrinthos).
9. **무작위 결정과 애니메이션 분리**(Fisher–Yates 후 연출, VP0 기술 블로그) — 우리 `deck.ts`의 덱 토큰 구조와 같습니다.
10. **뒤집기 0.5~1초, 차례로 공개, 모션 감소 시 페이드**(Labyrinthos 1s flipInY, 일반 플립 컴포넌트 500~600ms). → 여덟자 600ms(§9).

### 6.4 결론 — MVP는 A안 '먹선 카드'

1. **MVP: A안(자체 먹선 카드)**을 권장합니다.
   - 법적 위험이 가장 낮고, "먹과 여백"과 정확히 맞으며, 다크 모드·글자 확대·공유 이미지까지 코드 하나로 해결됩니다.
   - 국내 타로 앱 대부분이 원색 RWS 계열이거나 캐릭터 덱이라(§3), 무채색 기호 카드 자체가 차별점이 됩니다.
   - 1909년 그림의 정보는 콘텐츠의 `imagery` 문장(예: "검은 갑옷의 기사가 흰 장미 깃발을 들고…")을 '전통 카드 속 그림'으로 함께 보여 줘 보완합니다(§8.4).
2. **2차(선택): B안을 '고전 그림으로 보기' 토글로 추가**할 수 있습니다. 쓸 경우 조건은 다음과 같습니다.
   - 출처는 Wikimedia Commons **`Category:Rider-Waite tarot deck (Roses & Lilies)`**(1909년 초판, 78장 + 뒷면 2장, `RWS1909 - 00 Fool.jpeg` 형식)로 합니다 [확인]. 예비로 `Category:Rider-Waite-Smith tarot deck (TaionWC)`(Pam-A 판본, 약 1100×1920px)를 둡니다.
   - Commons의 `RWS Tarot NN` 파일들은 여러 차례 다른 판본으로 덮어쓰인 기록이 있습니다(2025-11 '복원판' 업로드 후 2026-04 되돌림) [확인]. 쓰는 **파일 리비전(타임스탬프·SHA1)을 고정**하고 우리 저장소에 사본을 둡니다.
   - US Games 판본이 아닌지 확인합니다: 뒷면이 장미·백합(1909) 또는 갈색 균열 무늬(Pam-A/C/D)여야 하고, 카드에 '© U.S. Games' 표기가 없어야 하며, 제목이 스미스의 손글씨여야 합니다.
   - 'Pamela Colman Smith (1909), public domain'을 표기하고, 'Rider-Waite' 브랜딩은 쓰지 않습니다.
3. C안(신규 일러스트)은 브랜드 확장 단계에서 검토하고, 계약 조건은 §6.1 표를 따릅니다.

### 6.7 역방향 표시

- 카드 앞면 SVG 전체를 `transform: rotate(180deg)`로 돌립니다(이름 글자도 함께 거꾸로 — 실제 카드를 뒤집어 놓은 모습 그대로).
- **카드 아래 UI 텍스트(정방향으로 읽힘)**에 `탑 · 역방향`처럼 라벨을 함께 둡니다. 회전만으로 전달하지 않습니다(스크린리더·숫자 카드처럼 모양이 대칭인 카드 대응).
- 역방향 라벨은 경고색을 쓰지 않습니다. `text-ink-3` + 작은 회전 화살표 아이콘(↻, `aria-hidden`)만 둡니다.
- 역방향은 기본값 **켜짐**을 권장하되, 질문 화면과 타로 설정에서 끌 수 있게 합니다(`tarot.question.reversedToggle`). 처음 쓰는 사용자가 역방향을 '나쁜 카드'로 오해하지 않게 결과 화면에 `tarot.result.reversedNote`를 한 번 보여 줍니다.

| 안 | 내용 | 판단 |
|---|---|---|
| A. 무채색 (권장) | 앞면은 먹선(`--text-1`) + 한지 바탕(`--surface`)만. 색은 뒷면 낙관(인주색) 하나 | ✅ 채택 |
| B. 무채색 + 강조색 1개 | 메이저 번호를 금색(`--gold`)으로 | ✕ `--gold`는 이미 '프리미엄·잠금 해제' 의미로 쓰고 있어 "메이저 = 유료"로 오해할 수 있음 |
| C. 수트를 오행 색에 대응 | 완드=木/火, 컵=水, 소드=金, 펜타클=土 | ✕ 아래 이유 |

C안을 쓰지 않는 이유
1. **"색은 오행의 것" 규칙 위반**입니다. 사주 화면에서 木 초록은 '내 명식의 木'이라는 데이터입니다. 타로 카드가 같은 초록을 쓰면, 사용자는 '이 카드가 내 木과 관련 있다'고 잘못 읽습니다.
2. **대응이 억지입니다.** 서양 전통(골든 던 계열)에서 완드는 불, 컵은 물, 소드는 공기, 펜타클은 흙입니다. 오행에는 '공기'가 없고, 완드는 재료로는 나무(木)이지만 원소로는 불(火)이라 어느 쪽을 골라도 한쪽 전통을 어기게 됩니다.
3. 수트 구별은 **무늬 + 텍스트 라벨**로 충분합니다(색각 이상 사용자에게도 같은 정보).
4. 무채색 카드는 다크 모드에서 변수만 바꾸면 그대로 반전되고, 공유 이미지에서도 '여덟자다운' 판화 느낌을 유지합니다.

### 7.2 법적 경계

- **표시광고법 제3조**: 거짓·과장·기만 광고 금지. 위반하면 제17조에 따라 2년 이하 징역 또는 1억 5천만원 이하 벌금 [확인], 관련 매출 2% 이내 과징금 [인용].
- **공정위 '추천·보증 등에 관한 표시·광고 심사지침'**(예규 제499호, 2026-06-01 시행) [확인]
  - '전문가'로 추천하려면 **실제로 그 전문성을 갖춰야** 합니다.
  - 후기는 실제 경험을 반영해야 합니다.
  - AI로 만든 가상 인물은 **'가상의 전문가 포함'처럼 표시**해야 합니다.
  - 가상 인물의 경험을 실제처럼 표현하면 **표시를 해도 기만**에 해당합니다.
  - → 가상의 '○년 경력 타로 마스터', AI 페르소나에 붙인 경력, 만든 후기는 모두 고위험입니다.
- **인공지능 기본법**(법률 제20676호, 2026-01-22 시행) 제31조 [확인]
  - ① 생성형 AI 기반 서비스임을 **미리 고지**해야 합니다(약관·화면 등, 시행령 제23조①).
  - ② 결과물이 AI로 생성됐음을 **표시**해야 합니다(시행령 제23조②).
  - 사전 고지를 위반하면 과태료 최대 3천만원(제43조)입니다. 계도기간이 1년 이상이라는 보도가 있습니다 [인용].
  - → 우리 카피: 결제 전 `paywall.aiNotice`(사전 고지), 결과의 `result.aiBadge` + `disclaimer.ai`(결과물 표시), `about.ai`.
- **저작권법 제14조②**(사후 저작인격권): 1909년 원화를 쓸 경우 작가 표기(§6.2).

### 7.3 여덟자 권장안 — "사람 대신 기준을 보여 준다"

1. **해석 기준 공개**: 타로 홈과 결과 하단에 '여덟자 타로는 이렇게 읽어요'(`about.*`) 시트를 둡니다.
   - 담을 내용: 78장·1909년 전통 해석, 카드 그림 출처, 무작위 방식(조작 없음), 역방향 규칙, AI 표시 원칙, 콘텐츠 작성 원칙(`about.review`), 출판사와 제휴 없음(`about.notAffiliated`).
   - 사주 쪽의 '보정 내역 공개'와 같은 '투명함' 축입니다(`02` §7.2).
2. **카드마다 근거**: '이렇게 읽은 이유'(`result.whyBody`)로 "자리 + 카드 + 전통 키워드"를 밝힙니다. 권위자의 이름 대신 **읽는 방법**이 신뢰의 근거가 되게 합니다.
3. **숫자는 실제 집계만, MVP에서는 쓰지 않음**: "○만 명의 선택", "적중률", "1위"는 쓰지 않습니다(`04` §8). 나중에 쓰더라도 정의와 기준일을 함께 표기합니다(예: "2026년 11월 한 달 동안 펼친 카드 ○장").
4. **실제 자문가를 둘 때만 크레딧**
   - 조건: 실명 또는 확인 가능한 활동명, **검증 가능한 이력만**, 역할 범위를 명시(예: "카드 의미 156개 문장 감수"), 계약서와 증빙 보관, 사진은 본인 동의.
   - 표기 위치: `about` 시트 하단 한 줄. 예) "카드 해석 감수: ○○○ (확인된 이력 한 줄)".
   - 이 문구는 실제 계약 전에 화면에 노출되지 않도록 **`copy-tarot-ko.json`에 넣지 않았습니다**.
   - 사주아이처럼 '자문을 거쳐 설계'라고 역할을 한정하는 표기는 좋은 형식이지만, 경력 숫자는 증빙이 있을 때만 씁니다.
5. **가이드 캐릭터: MVP에서는 권장하지 않습니다.**
   - 브랜드 일관성: 여덟자의 시각 앵커는 낙관(도장) 하나이고, 화자는 '다정한 해석가' 문체 자체입니다. 캐릭터를 더하면 사주(캐릭터 없음)와 타로의 인상이 갈라집니다.
   - 차별화: 국내 타로는 거의 모두 캐릭터·페르소나(라마마, 아이샤, 도사, 모찌요정)를 씁니다. 캐릭터가 없는 조용한 타로가 오히려 빈자리입니다(§0).
   - 위험: 캐릭터가 AI 풀이를 '말하는' 순간 AI를 사람처럼 위장하지 말라는 원칙(`04` §5.4)과 가상 인물 표시 의무(§7.2)를 계속 관리해야 합니다.
   - 2차에 검토한다면: 사람·동물 실사가 아닌 **먹선 상징형**, 이름 하나, 반말 금지, "AI가 쓴 풀이"를 캐릭터 말풍선에도 표시.
6. **전문가 1:1 상담(사람 리더 마켓)**은 PRD상 '보류(레드오션)'이므로 타로에서도 다루지 않습니다.

## 8. 여덟자 타로 화면 설계안

> 와이어프레임의 카드·문장·날짜는 레이아웃 확인용 더미입니다. 문구 키는 `copy-tarot-ko.json` 기준(`tarot.` 접두어 생략)입니다.

### 8.0 정보구조(IA)와 진입점

```
/tarot                 타로 홈 (주제 선택 · 오늘의 카드 · 최근 기록)
/tarot/daily           오늘의 카드 (뽑기 → 결과, 하루 1장 고정)
/tarot/ask?topic=love  질문 입력 (펼침 방식 자동 추천, 바꾸기 가능)
/tarot/draw            섞기 → 고르기 → 펼치기 (한 화면 안의 3단계, 뒤로 가기 = 이전 단계)
/tarot/r/:readingId    결과 (무료 + 깊은 풀이 잠금)
/tarot/history         기록 (보관함)
```

- **하단 탭은 5개를 유지**합니다(iOS 권장 최대치, `02` §7.7). 타로 진입점은 세 곳입니다.
  1. **오늘 탭**: 오늘의 운세 아래에 '오늘의 카드' 모듈(카드 뒷면 + `home.dailyCard.cta`). 매일 쓰는 습관(푸시 08:00)과 자연스럽게 이어집니다.
  2. **물어보기 탭**: 상단 세그먼트 `사주에게 묻기 | 타로로 묻기`(`meta.askSegment`). 타로는 '질문으로 시작하는' 기능이라 탭 이름과 맞습니다.
  3. **데스크톱 상단 내비**: `오늘 · 내 사주 · 궁합 · 물어보기 · 타로 · 만세력`(`meta.navLabel`).
- 결과는 **로그인 없이** 볼 수 있습니다(`02` §7.8 "결과를 먼저, 가입은 나중에"). 저장·다른 기기 동기화·결제 시점에 로그인을 요청합니다. 게스트 기록은 기기에 저장하고 `history.guestNote`로 알립니다.

- 질문 최대 길이 80자 권장[추정 — LLM 입력·공유 카드 미리보기 기준]. 양자택일 선택지는 각 20자.
- **민감 질문 안내**(입력 중 키워드 감지, 막지 않고 안내만): 건강·법률·투자 → `question.sensitive.expert`, 특정인의 마음 단정 → `question.sensitive.thirdParty`, 자해·자살 신호 → `question.sensitive.crisis`(풀이 진행 전에 노출, `04` §5.7 위기 대응과 같은 문구).
- 돈 주제 결과에는 `disclaimer.expert`(투자 조언 아님)를 고정 노출합니다(`04` §6.10 `disclaimer.finance`와 같은 원칙).

### 8.3 섞기 · 고르기 · 펼치기 (`/tarot/draw`)

한 경로 안의 3단계입니다. 상단에 **단계 표시(1 섞기 · 2 고르기 · 3 펼치기)**와 뒤로 가기를 둡니다(`02` §7.10 스텝형 원칙).

```
[1 섞기]                              [2 고르기]

│ ←   ● 섞기 ○ 고르기 ○ 펼치기│        │ ←   ✓ 섞기 ● 고르기 ○ 펼치기│
│                           │        │ 카드 3장을 골라 주세요  1/3 │
│ 카드를 섞고 있어요          │        │ 끌리는 카드를 천천히 …      │
│ 궁금한 것을 마음속으로 한 번│        │ ┌───┐ ┌───┐ ┌───┐          │ 자리 슬롯 88×151
│ 떠올려 보세요.              │        │ │▦▦ │ │   │ │   │          │ (4장이면 76×130, 자리 이름은 아래)
│                           │        │ └───┘ └───┘ └───┘          │

│      └────┘┘              │        │  ╰─────────────────────╯  │ 보이는 폭 44px/장
│                           │        │  ← 옆으로 넘기며 고를 수 … │
```

- **섞기**: 진입하면 자동으로 1회 섞고(약 1.2초), '한 번 더 섞기'로 반복할 수 있습니다. 실제 순서는 `crypto.getRandomValues` 기반 Fisher–Yates로 정하고, 애니메이션은 그 결과를 연출만 합니다(애니메이션 길이와 무작위성은 무관 — 가짜 대기 금지, `02` §7.12).
- **자리 안내**: 고르기 화면 제목 아래에 지금 채울 자리를 보여 줍니다 — `pick.positionPrompt` "'걸림돌' 자리를 떠올리며 골라 보세요." + 해당 자리의 `hint`. 다음 빈 슬롯은 점선 테두리로 강조합니다(헬로우봇·포스텔러의 자리별 고르기 패턴, §5.1).
- **고르기**: 78장을 모두 가로 띠로 펼칩니다. (대안: 도사식 '가운데 카드 선택' 캐러셀은 카드가 커서 누르기 쉽지만 78장을 넘기기에 느려, 띠 + 자유 선택을 기본으로 둡니다.) 장마다 보이는 폭 44px(터치 영역 44×123)입니다. 띠 가운데에 가까운 카드는 살짝 위로(최대 8px) 올려 **완만한 부채꼴**처럼 보이게 합니다(스크롤 위치 기반, 모션 감소 시 평평하게).
  - 카드를 누르면 12px 떠오른 뒤 다음 빈 슬롯으로 이동해 놓입니다.
  - 고른 순서 = 자리 순서입니다(첫 장 = 첫 자리).
  - '마지막 카드 되돌리기'로 한 장씩 취소할 수 있고, 다 고르면 띠를 흐리게(opacity .4) 처리하고 '카드 펼치기'를 활성화합니다.
  - **'알아서 골라 주세요'**는 남은 장수만큼 무작위로 골라 슬롯을 채웁니다(빠른 경로이자, 제스처가 어려운 사용자를 위한 대안).
- **펼치기**: 기본은 **한 장씩 탭해서 펼치기**(사용자가 속도를 정함)이고, '한 번에 펼치기'를 누르면 320ms 간격으로 차례로 뒤집힙니다(§9). 펼친 카드 아래에 `카드 이름 · 정/역방향` 텍스트를 바로 보여 줍니다.
- 풀이 생성(LLM 또는 규칙)은 **'카드 펼치기'를 누르는 순간 요청을 시작**해 펼치는 동안 준비합니다. 모두 펼친 뒤에도 준비가 덜 됐으면 결과 화면에서 섹션 단위 스켈레톤 + `loading.*` 문구를 씁니다(`02` §7.12 두 단계 로딩과 같은 원칙).

**탭 수 (연애 4장 기준)**: 주제 1 → 질문 입력 또는 '건너뛰기' 1 → 섞기 '카드 고르기' 1 → 카드 4 → '카드 펼치기' 1 → (펼치기 4 또는 '한 번에' 1) → '풀이 읽기' 1 = **최소 10탭**, '알아서 골라 주세요'를 쓰면 **7탭**. 오늘의 카드는 '오늘의 카드 뽑기' 1 → 놓인 카드 한 장 탭해서 펼치기 1 = **2탭**입니다(78장 띠 없음 — §9 무작위 메모 참고).

- **카드 블록 구조(고정)**: `자리 라벨 → 카드 이름·정/역 → 키워드 3개 → 한 줄 요약(summary) → 카드의 뜻(전통, 무료) → 전통 카드 속 그림(imagery, 접어 두기) → 이 자리에서 읽으면(질문 맞춤) → (펼치기) 이렇게 읽은 이유`. 필드 이름은 콘텐츠 타입 계약(`apps/api/src/modules/tarot/content/types.ts`의 `keywords · summary · general/love/feelings/career/money · advice · imagery`)과 맞췄습니다.
- **'전통 카드 속 그림'**: 우리 카드는 상징만 남긴 먹선 카드이므로, 1909년 카드에 그려진 장면을 `imagery` 한 문장으로 보여 줍니다(`result.imageryLabel`·`imageryNote`). 그림 없이도 전통 상징을 읽을 수 있게 하는 장치이고, 스크린리더 사용자에게도 같은 정보를 줍니다. '이렇게 읽은 이유'는 `result.whyBody`로 "자리 + 카드 + 전통 키워드"를 밝혀 투명함 원칙(`02` §7.2)을 지킵니다.
- **무거운 카드 안내**: 죽음·탑·악마·소드 10이 나오면 해당 블록 위에 `result.heavyCards.*`를 회색 안내 상자로 보여 줍니다. 공포 조장 금지(`04` §5.4)의 화면 버전입니다.
- **예·아니오**: 숫자나 '정답' 대신 3단계 기울기 막대(`아니오 쪽 ── 열려 있음 ── 예 쪽`)와 `result.yesno.*` 문장을 씁니다. 키는 콘텐츠의 `yesNo: 'yes' | 'no' | 'maybe'`와 같은 이름(`result.yesno.yes/no/maybe`)입니다. 큰 'YES/NO' 단독 표시는 쓰지 않습니다(단정 대신 경향).
- **양자택일**: A·B 두 열을 나란히 두고(모바일은 세로로 쌓되 같은 순서) `choice.compareTitle`. 한쪽을 '정답'으로 표시하지 않습니다.
- **오늘의 카드 결과**: 한 장 상세(168×288) + 카드가 건네는 한 줄 + 카드의 뜻 + 이렇게 해 보세요 1~2개 — **전부 무료**, 잠금 없음. 하단에 광고 슬롯 허용(무료 결과).

### 8.5 무료/유료 경계 (정직한 잠금)

| 영역 | 오늘의 카드 | 질문 타로(1~4장) | 켈틱 크로스(10장, 2차) |
|---|---|---|---|
| 뽑은 카드 이름·그림·정/역 | 무료 | 무료 | 무료 |
| 카드 키워드·전통 의미 | 무료 | 무료 | 무료 |
| 카드가 건네는 한 줄 | 무료 | 무료 | 무료 |
| 자리별 질문 맞춤 풀이 | — | **첫 문장 공개 + 페이드** → 유료 | 유료 |
| 총평 | 무료(짧게) | **첫 문단 공개 + 페이드 + 목차** → 유료 | 첫 문단 공개 → 유료 |
| 이렇게 해 보세요 | 무료 1~2개 | 무료 1개 / 유료 3개 | 유료 |
| 흐름이 바뀌는 신호 · 다음 질문 | — | 유료 | 유료 |
| 메모 · 기록 저장 · 공유 | 무료 | 무료 | 무료 |

원칙
1. **카드는 절대 가리지 않습니다.** 무엇을 뽑았는지와 그 카드의 전통적인 뜻은 공개 지식이므로 항상 무료입니다. 잠그는 것은 '질문에 맞춘 해석 노동'뿐입니다.
2. **결제해도 카드는 그대로**(`paywall.sameCards`). 다시 뽑기·카드 추가·'더 좋은 카드' 같은 결과를 바꾸는 상품은 만들지 않습니다(도박성·반복 결제 유도 방지).
3. 잠금 UI는 기존 `ReadingSection`과 같습니다: 실제 첫 문단 → 60px 페이드(`.fade-out-bottom`) → 금색 테두리 잠금 카드 + 실제 유료 목차 → CTA. 텍스트 블러는 쓰지 않습니다.
4. 결제 단위는 **질문권 1회**를 1순위로 권장합니다. 이미 있는 원장(유상/무상 분리, 유효기간 없음)을 그대로 쓰고, "범용 코인 없음" 원칙도 지킵니다. 단건 원화 판매(`{{price}}`)는 대안입니다. 금액·무료 횟수(예: 질문 타로 하루 N회)는 마케팅팀이 정합니다.
5. 결제 후에는 0.3초 페이드로 잠금을 풀고 **읽던 위치를 유지**합니다(PRD §4).
6. 광고: 무료 결과 하단에만. 섞기·고르기·펼치기(입력에 해당), 결제 시트, 깊은 풀이를 연 결과에는 넣지 않습니다(PRD §3).

### 8.6 공유

- 공유 버튼은 결과 우상단 + 하단 액션 두 곳, 같은 위치 규칙(`02` §6).
- **이미지 카드 1080×1350**: 한지 바탕 → 상단 `share.card.spreadLabel` 또는 `dailyLabel` → 카드 앞면(1장 540×926 / 3장 300×514 가로 배치) → 카드가 건네는 한 줄(명조) → 하단 낙관 + `share.card.footer` + 짧은 URL.
- **질문·메모는 기본으로 넣지 않습니다**(`share.privacyNote`). 토글 `includeQuestion`을 켤 때만 넣고, 이름도 토글(`includeName`).
- **공유 결과 페이지는 `<meta name="robots" content="noindex">`**로 두고 사이트맵에 넣지 않습니다. 질문은 URL·OG 태그에 절대 넣지 않습니다(운빨 사이트맵이 질문 원문 111건을 검색에 노출한 사례, §3.2).
- 카카오: `share.kakaoDaily` / `kakaoSpread`(제목·설명 2줄 이내, 버튼명 8자 이하 — `04` §6.9 제약).
- OG 이미지 1200×630: 카드 앞면 + 한 줄. 받는 사람의 CTA는 "나도 뽑아 보기"(→ `/tarot/daily`).

## 9. 인터랙션 사양

모든 전환은 기존 토큰 `--ease-ink: cubic-bezier(0.2, 0.8, 0.2, 1)`과 `02` §7.6의 길이 토큰(fast 120 / base 200 / slow 320ms)을 기준으로 합니다. 타로 전용 길이 3개(`--dur-flip` 600, `--dur-fly` 400, `--dur-shuffle` 280)를 추가합니다. 뒤집기 600ms는 레퍼런스(Labyrinthos 웹 flipInY 1초, 일반 플립 컴포넌트 500~600ms, VP0 "거의 1초")보다 약간 빠른 쪽으로, '읽는 앱'의 템포에 맞춘 값입니다.

| 순간 | 동작 | 길이 · 이징 | 모션 감소 시 |
|---|---|---|---|
| 섞기 1회 | 더미를 두 뭉치로 나눠 좌우로(±24px, ±4°) 벌렸다가 엇갈려 합침 | 280ms × 3회 + 정착 320ms ≈ **1.2초**, `--ease-ink` | 애니메이션 없음. 더미 그대로 + `shuffle.reducedMotion` 문구 페이드 200ms |
| 띠로 펼치기 | 더미 위치에서 띠 위치로 퍼짐, 카드마다 지연. **화면에 보이는 카드(모바일 약 8장, 데스크톱 약 40장)만 애니메이션**하고 나머지는 제자리에 바로 둠(성능) | 320ms, 지연 30ms/장(최대 300ms), `--ease-ink` | 띠가 그 자리에서 페이드 인 200ms |
| 띠 부채꼴 | 스크롤 위치에 따라 가운데 카드가 최대 8px 올라옴 | 스크롤 연동(애니메이션 아님) | 평평한 띠 |
| 카드 누름 | 12px 떠오름 | 120ms (`fast`) | 테두리 강조만 |
| 슬롯으로 이동 | 띠 → 빈 슬롯으로 날아가며 크기 72→88 | **400ms**, `--ease-ink` | 띠 카드가 사라지고 슬롯에 페이드 인 120ms |
| 뒤집기 | Y축 3D 회전 180°(`perspective: 800px`, `backface-visibility: hidden`), 역방향은 회전이 끝난 뒤 면을 180° 돌린 상태로 놓임. 뒤집은 뒤 200ms 멈췄다가 카드 아래 이름 라벨 페이드 인 | **600ms**, `--ease-ink` | 3D 없음. 뒷면→앞면 크로스페이드 200ms linear. 역방향 카드는 처음부터 돌린 상태로 표시(의미 정보이므로 유지) |
| 한 번에 펼치기 | 왼쪽부터 차례로 뒤집기 | 320ms 간격 (3장 ≈ 1.24초, 4장 ≈ 1.56초) | 한꺼번에 페이드 200ms |
| 결과 진입 | 페이지 페이드 + 카드 줄 고정 | 200ms (`base`) | 같음(페이드만) |
| 잠금 해제 | 잠금 카드 사라지고 본문 펼쳐짐 | 300ms 페이드, 스크롤 위치 유지 | 같음 |
| 햅틱(앱만) | 카드 고를 때 Light, 뒤집을 때 Light | Capacitor Haptics `ImpactStyle.Light` | 설정 `tarot.settings.haptics`로 끌 수 있음. 웹은 생략 |

- **모션 감소 판정**: `prefers-reduced-motion: reduce` 또는 앱 설정 '카드 움직임 줄이기'(`tarot.settings.motion`) 중 하나라도 켜지면 적용합니다. 기존 `index.css`의 `@media (prefers-reduced-motion: reduce)` 블록에 타로 클래스(`.animate-shuffle`, `.animate-flip`, `.animate-fly`)를 추가하는 방식입니다.
- 번쩍임 금지: 탑 카드의 번개도 정적인 선이고, 깜빡이는 효과는 쓰지 않습니다(WCAG 2.3.1).
- 소리: 기본 없음.
- **무작위·기록의 정직성(개발 메모)**
  - 질문 타로: 개발 중인 `apps/api/src/modules/tarot/deck.ts`의 설계와 같습니다. '섞기' 때 서버가 임의 시드로 **덱 토큰**(HMAC 서명, 30분 만료)을 발급하고, 카드 순서는 클라이언트에 보내지 않습니다. 사용자가 고른 **자리 번호(0~77)**만 서버로 보내면 서버가 같은 순서를 재현해 카드를 꺼냅니다. 같은 토큰으로 리딩을 두 번 만들 수 없으므로, 깊은 풀이는 처음 펼친 카드로만 생성됩니다(`paywall.sameCards` 약속의 기술적 근거). 섞기 애니메이션은 토큰 발급을 기다리는 동안 재생하되, 응답이 늦으면 애니메이션을 늘리지 말고 '다 섞었어요' 전환만 늦춥니다.
  - 오늘의 카드: `dailyCard(userId, isoDate)` — 같은 사람·같은 날은 하루 종일 같은 카드입니다(`home.dailyCard.oncePerDay`). 결과가 이미 정해져 있으므로 '고르기'를 연출하지 않고, 78장 띠 대신 **놓인 카드 한 장을 탭해서 뒤집기**만 둡니다(고르는 척만 하게 만드는 연출을 피함). 게스트는 기기 ID 기준입니다.
  - 역방향 확률은 `deck.ts`의 `REVERSED_RATE = 0.35`(35%)입니다. 설정에서 역방향을 끄면 모두 정방향으로 읽습니다(카드 자체는 그대로, 해석만 정방향 사용 — 서버 정책 확인 필요).

## 13. `copy-tarot-ko.json` 사용 가이드

- 최상위 키는 `tarot` 하나입니다. `apps/web/src/i18n/ko.json`에 `"tarot": { … }`를 그대로 합치면 기존 `t('tarot.home.title')`로 쓸 수 있습니다.
- 하위 키: `meta, home, topics, spreads, question, shuffle, pick, reveal, loading, result, paywall, share, history, about, settings, disclaimer, empty, error, a11y, cards`.
- **배열을 쓰지 않았습니다.** 기존 `t()`(`apps/web/src/lib/copy.ts`)는 문자열만 돌려주고 `ko.json`에도 배열이 없어서, 자리 목록은 `spreads.three.positions.0.label`처럼 **인덱스 키 객체**로 넣었습니다. 순서대로 쓰려면 `Object.keys(positions)`(정수 키는 오름차순 보장)로 돌리면 됩니다. 질문 예시(`question.examples.{topic}.0…`)도 같은 방식입니다.
- 보간은 기존과 같은 `{{var}}`입니다. 변수: `card, cards, count, date, day, headline, index, keyword, max, month, name, numeral, option, optionA, optionB, orientation, picked, position, price, rank, remaining, suit, topic`.
- 조사 규칙(`04` §5.5)을 지켜 변수 바로 뒤에 은/는·이/가·을/를·예요/이에요가 오지 않게 썼습니다(예: `'{{card}}' 카드가 …`, `'{{card}}' 카드({{orientation}})는 …`).
- 카드 이름의 1차 출처는 콘텐츠의 `nameKo`/`nameEn`입니다. `cards.*`는 카드 앞면 렌더링(번호·수트·계급 라벨)과 콘텐츠가 없을 때의 대체용입니다. `cards.ranks`의 키는 콘텐츠의 `number`(1 에이스 … 10, 11 페이지, 12 나이트, 13 퀸, 14 킹)와 같습니다. 마이너 카드 이름은 `cards.nameFormat`(`{{suit}} {{rank}}` → "컵 퀸", "완드 에이스")으로 조합합니다. 궁정 카드는 국내 타로 사용자가 가장 많이 쓰는 음차(페이지·나이트·퀸·킹)를 이름으로, 뜻풀이(`gloss`: 배우는 사람 …)를 보조로 둡니다.
- 문구 수: 문자열 498개(카드 이름 포함). 느낌표·이모지 0개, 변수 뒤 조사 0개(스크립트로 검사).
- 정책 확정 후 고칠 키
  - `paywall.ctaCredit`·`paywall.cta`: 결제 단위
  - `error.dailyLimit`: 무료 횟수
  - `error.aiFailed.body`: "질문권은 풀이가 끝났을 때만 차감돼요"가 실제 차감 정책과 같아야 함
  - `about.art`·`about.artClassic`·`settings.classicArt*`: 카드 그림 출처, 고전 그림 옵션을 낼 때만 노출
  - `result.basisNote`·`about.deck`·`about.notAffiliated`: 법무 검토 후 덱 표기
  - `spreads.celtic.comingSoon`
- 일부러 넣지 않은 문구: 자문가 크레딧(실제 계약 전 노출 방지, §7.3), 사용자 수·순위 같은 숫자.
