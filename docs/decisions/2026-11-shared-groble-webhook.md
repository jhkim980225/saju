# 그로블 계정을 다른 서비스와 같이 쓰고, ref 접두어로 구분하며 웹훅은 넘겨받는다

- 날짜: 2026-11-25 (ref 접두어 코드는 2026-10-15)
- 상태: 채택
- 관련 커밋:
  - `738028f` 한 그로블 계정을 여러 서비스가 같이 쓰도록 ref 접두어(`GROBLE_REF_PREFIX`) 추가(2026-10-15)
  - `37dca41` 운영 연결: `GROBLE_REF_PREFIX=saju`, 그로블 웹훅은 청첩장 서비스가 받아 넘겨줌(2026-11-25)
- 관련 문서: [PAYMENTS.md](../PAYMENTS.md) §1.0·§3.5, [ENV_KEYS.md](../ENV_KEYS.md) §2, [features/payments.md](../features/payments.md), [2026-10-groble-web-payments.md](./2026-10-groble-web-payments.md)

## 맥락

웹 결제는 그로블 결제창으로 한다([2026-10-groble-web-payments.md](./2026-10-groble-web-payments.md)). 운영자의 그로블 판매자 계정은 같은 운영자의 청첩장 서비스도 쓰는 계정이다. 그로블 웹훅 주소는 스토어당 하나만 등록할 수 있다. 그로블 결제는 결제창 주소의 `ref` 를 웹훅의 `sellerReference` 로 돌려주고, 이 서비스는 그 값으로 주문을 찾는다.

## 결정

- 같은 그로블 계정을 쓴다. 이 서비스의 상품마다 결제창을 새로 만들어 붙인다.
- 서비스마다 ref 접두어를 다르게 둔다. 이 서비스는 `GROBLE_REF_PREFIX=saju` 라서 ref 가 `saju-<주문 ID>` 다(`apps/api/wrangler.jsonc` 의 vars).
- 다른 접두어의 결제 완료 알림은 다른 서비스의 것으로 보고 기록만 한다. ref 가 없는 환불 알림은 `merchantUid` 로 이 서비스의 주문이 있을 때만 회수하고, 없으면 경고 없이 넘어간다.
- 웹훅은 청첩장 서비스가 받는다. 청첩장 서버는 자기 결제가 아닌 알림을 본문과 서명 헤더를 바꾸지 않고 이 서비스의 그로블 웹훅 엔드포인트로 넘긴다. 두 서버는 같은 `GROBLE_WEBHOOK_SECRET` 으로 서명을 검증한다.
- 이 서비스가 4xx 나 5xx 로 실패하면 청첩장 서버가 그로블에 502 를 돌려주어 그로블이 다시 보내게 한다.

## 근거

- 그로블 웹훅 주소가 스토어당 하나이므로, 같은 계정을 쓰려면 한 서버가 받아 넘겨야 한다(PAYMENTS.md §1.0).
- PAYMENTS.md §1.0 은 그로블 멤버십이 판매자 계정 단위이고, 판매자 약관 제10조가 결제창을 붙인 외부 페이지 주소를 등록·유지하라고만 정해 서비스 수를 제한하지 않는다고 적는다.
- 접두어 방식은 웹훅 주소를 서비스마다 등록하든 한 주소로 받아 넘기든 같은 코드로 동작하게 하려는 것이다(`738028f`).
- 계정을 새로 만들지 않고 같이 쓰기로 한 직접적인 이유는 기록에 없다. TODO: 확인 필요.

## 결과와 영향

얻은 것:
- 그로블 판매자 계정을 새로 만들지 않고 2026-11-25 에 웹 결제를 연결했다.
- 접두어가 없으면 모든 알림을 이 서비스 것으로 보므로, 나중에 계정을 따로 쓰게 되어도 코드를 바꾸지 않고 설정만 바꾼다.

감수한 것:
- 이 서비스의 결제 확정이 다른 서비스의 전달 코드와 가동 상태에 달려 있다. 청첩장 서버가 멈추거나 전달 코드가 바뀌면 이 서비스에 웹훅이 오지 않는다. 이때 운영자는 결제 확인 지연 알림(미결 주문 30분)으로 알게 된다(features/payments.md).
- 두 Worker 가 같은 웹훅 시크릿을 쓴다. 그로블에서 시크릿을 재발급하면 24시간 안에 두 Worker 모두에 새 값을 넣어야 한다.
- 판매자 이름, 정산, 세금계산서, 환불 화면이 두 서비스에 하나로 합쳐진다. 운영자는 그로블 판매자 화면에서 두 서비스의 결제를 함께 본다.
- 청첩장 서비스의 운영 알림은 청첩장 결제와 테스트 발송에만 오고, 이 서비스로 넘긴 알림은 이 서비스의 운영 알림이 맡는다.
