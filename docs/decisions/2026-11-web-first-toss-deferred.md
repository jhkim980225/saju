## 맥락

서비스는 웹, Android·iOS 앱(Capacitor), 토스 앱 안의 미니앱 세 경로로 낼 수 있게 만들어졌다. 소셜 로그인 4종, 비밀번호 재설정 메일(Resend), 푸시(FCM), 광고, 분석 도구는 코드가 있고 외부 키를 넣으면 켜진다. 토스 미니앱은 별도 빌드(`npm run build:toss -w @saju/web`, `apps/web/src/toss/*`)와 서버 엔드포인트가 있다.

## 결정

- 웹을 먼저 출시한다. 2026-11-25 에 운영 도메인 daldalsaju.com 과 그로블 결제를 연결했다. 이날 기준 운영 설정에서는 이메일 가입·로그인, 그로블 결제, AI 기능이 켜져 있다.
- 토스 미니앱은 웹 출시 뒤로 미룬다. 서버와 토스 사이의 mTLS 인증서 바인딩(`TOSS_MTLS`)을 `wrangler.jsonc` 에 넣지 않아 토스 로그인·결제·광고 기능은 꺼져 있다.
- iOS 빌드와 서명은 출시 준비 시점에 macOS 또는 CI `ios` 잡으로 한다.
- 외부 서비스는 키를 발급받은 뒤 실연동을 검증한다. 그때까지 키가 없는 기능은 꺼진 채로 둔다.

## 결과와 영향

얻은 것:
- 외부 키를 모두 갖추기 전에 웹 하나로 결제와 AI 기능을 운영할 수 있게 되었다.

감수한 것:
- 코드는 있지만 꺼진 기능이 많다(FEATURES.md §0.2·§22.1). 로그인 화면에는 이메일 로그인만 보인다. 비밀번호 재설정은 문의 안내로 바뀌는데 `SUPPORT_EMAIL` 이 비어 있어 받는 주소가 없다. 분석 도구가 꺼져 있어 `purchase` 같은 전환 이벤트가 기록되지 않는다. 웹 광고와 카카오톡 공유도 꺼져 있다.
- 꺼진 기능은 운영 환경에서 실제 외부 서비스와 연결해 본 적이 없다.
- 토스 미니앱은 보류 중에도 코드를 유지해야 한다. 토스 결제는 리포트·타로에 딸린 질문권을 주지 않고, 환불 알림이 없어 Cron 이 하루 한 번 환불 여부를 다시 확인하는 별도 규칙이 있다(FEATURES.md §21).
- 앱 인앱결제, 푸시, 보상형 광고는 앱 전용이라 앱 출시 전까지 쓰이지 않는다.
