# 화면 테마를 "먹과 여백"에서 "밤하늘과 달빛"으로 바꾼다

- 날짜: 2026-10-16 (기본 테마를 밝은 화면으로 돌린 것은 2026-11-23 사용자 결정이고, 커밋은 2026-11-25)
- 상태: 채택 (2026-11-23 부터 기본 테마는 흰 바탕의 밝은 화면이고, 밤하늘은 마이에서 고르는 테마로 남았다)
- 관련 커밋:

  - `4846e3c` 서비스명 변경 때 로고 글자만 바꾸고 초승달 로고와 밤하늘 디자인은 유지(2026-11-11)
  - `37dca41` 기본 테마를 흰 바탕의 밝은 화면으로 변경, 토스 미니앱은 밝은 화면만 사용(2026-11-25)

## 맥락

첫 커밋의 디자인 원칙은 리서치(research/02-ui-ux-analysis.md, 2026-10-12)가 권한 "먹과 여백"이었다. 한지색 바탕(`#F7F3EC`)과 먹색 글자로 화면을 만들고 색은 오행 데이터에만 쓰는 방식이고, PRD §1 은 이를 "국내에 없는 절제된 동양 미니멀"로 적었다. 앱 아이콘은 한지 바탕에 인주색 낙관과 음각 초승달이었고, 테마 기본값은 기기 설정(`system`)이었다. 2026-10-16 에 남색 밤하늘, 황금 초승달, 붓글씨 서비스명으로 된 새 로고 이미지가 저장소 루트 `image/` 폴더에 들어왔다.

## 결정

- 화면 전체를 새 로고에 맞춘 "밤하늘과 달빛" 테마로 바꾼다. 남색 바탕, 달빛 상아색 글자, 금빛 버튼을 기본으로 하고, 밝은 화면(상아색 바탕, 남색 글자)과 기기 설정은 마이에서 고른다.
- 유채색은 금빛(브랜드)과 오행 데이터에만 쓴다. 선택 상태(양력/음력, 칩, 선택 카드, 하단 탭)는 금빛으로 표시한다.
- 첫 화면 위쪽에는 잔별이 있는 밤하늘 패널(`.night-sky`)과 큰 초승달을 둔다. 이 패널은 밝은 화면에서도 남색이다.
- 로고 원본에서 남색 바탕을 걷어 낸 웹 로고 조각(`apps/web/public/brand/*.webp`)을 만든다. 파비콘, 홈 화면 아이콘, 공유 이미지, manifest, theme-color, Android·iOS 앱 아이콘과 스플래시도 새 로고로 바꾼다.
- 같은 날 밤하늘 남색을 한 단계 진하게 했다. 바탕은 `#0a1029` 에서 `#060b24` 로, 카드는 `#111938` 에서 `#0c1434` 로 바꿨다.

## 결과와 영향

얻은 것:
- 로고, 앱 아이콘, 스플래시, 화면 색이 같은 남색과 금빛을 쓴다. 서비스명을 달달사주로 바꿀 때도 초승달 로고와 밤하늘 디자인은 그대로 두고 로고 글자만 바꿨다.

감수한 것:
- 오행 색을 남색 카드 위에서 다시 맞춰야 했다. 오행 도넛 차트에는 전용 색을 따로 두고, 원에서 맞닿는 이웃 오행끼리 3:1 이상의 대비가 나게 했다.
- 웹 로고는 바탕을 걷어 낸 투명 그림이라 남색 위에서만 또렷하다. 밝은 화면의 헤더는 남색 앱 아이콘과 남색 글자로 바꿔 쓴다(`apps/web/src/components/Seal.tsx`).
- 두 테마의 색 토큰을 모두 유지해야 한다. 리포트 PDF 는 어두운 테마에서도 밝은 테마로 인쇄한 뒤 되돌리고, 사주 요약 화면은 밤하늘 테마에서도 흰 종이로 보이도록 `.paper` 로 밝은 토큰을 쓴다.
- 앱 아이콘과 스플래시 PNG 가 커졌다. 예를 들어 iOS 스플래시 한 장은 약 41KB 에서 약 779KB 가 되었다.
- 2026-11-23 결정으로 기본 테마가 흰 바탕, 남색 글자, 남색 버튼의 밝은 화면이 되어, 처음 방문한 사용자는 밤하늘 테마를 보지 않는다. 첫 화면의 밤하늘 패널만 남색 띠로 남는다. 토스 미니앱은 앱인토스 비게임 체크리스트 때문에 밝은 화면만 쓴다.

남은 일:
- PRD §1 은 아직 남색 바탕이 기본이라고 적는다. 코드(`apps/web/src/lib/theme.ts` 의 기본값 `light`)와 다르다.
- Android 알림 아이콘 `ic_stat_yd` 는 예전 초승달 벡터 그대로다(APP_PORTING.md §10).
- research/02 의 디자인 토큰 표와 research/05·06 의 일부 판단 근거는 "먹과 여백"을 기준으로 남아 있다.
